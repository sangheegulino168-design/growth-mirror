# 模型接入与训练策略

## 决策

首版不从零训练大模型。使用统一 `ModelAdapter` 接入现成云端 API；隐私敏感和离线场景可以换成本地预训练模型。认知内核在没有大模型时也必须能够运行和测试。

## 为什么不从零训练

- 项目创新点是长期成长、记忆遗忘、多因素归因和安全自主，不是基础语言能力。
- 从零训练需要大量语料、算力、评测和安全对齐投入。
- 把人格放进模型权重会降低可解释性、可回放性和用户数据删除能力。
- 在线用单个用户对话持续训练容易放大偏见、被渐进教坏并造成隐私风险。

## 模型职责

允许：

- 把用户表达分析为候选养育信号和冲突标签。
- 从引擎提供的记忆中生成自然、年龄适配的表达。
- 给出不确定度和候选解释。

禁止：

- 直接改变人格、关系、记忆强度或伦理规则。
- 把未检索到的过去编造成记忆。
- 决定镜像报告的证据编号。
- 通过提示词覆盖状态引擎。

## 三种运行模式

| 模式 | 用途 | 优点 | 代价 |
|---|---|---|---|
| 云端 API | MVP 和语言质量验证 | 上线快、表达稳定 | 成本、网络和隐私审查 |
| 本地预训练模型 | 离线与隐私版本 | 数据可留在设备 | 硬件要求、质量波动 |
| 后期微调模型 | 分类或表达优化 | 可稳定产品风格 | 需要经授权、去隐私的高质量数据 |

微调只能优化分类和语言风格，不承担伦理内核与成长状态。任何研究参与者数据进入训练集前必须重新取得明确同意，并允许撤回。

## 切换模型不改变人格

孩子的长期状态保存在版本化事件和状态快照中。更换 API、升级模型或切换本地模型后，需要用固定场景回归测试表达质量，但记忆、人格、价值来源和成长轨迹不应丢失。

## 运行配置

通用适配器读取以下环境变量：

- `GROWTH_MIRROR_LLM_BASE_URL`：OpenAI-compatible 服务地址。
- `GROWTH_MIRROR_LLM_MODEL`：模型名称。
- `GROWTH_MIRROR_LLM_API_KEY`：可选密钥，只从当前进程环境读取。
- `GROWTH_MIRROR_DB_PATH`：可选本地数据库路径。

未同时提供服务地址和模型名称时，系统自动使用确定性测试适配器，不会偷偷调用外部服务。
